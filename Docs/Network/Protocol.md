
# Packet

Packet has size and pointer to first byte. Its size should be within the range \[1, 1024\] bytes.

## Structure

Part of the packet can be technical information, compressed or encrypted data.
Content of packet, [] - optional, <> - variants of information edition:

`<<(content) encryption> compression>[6B, checksum][1B, nack id](1B, code and flags)`

### Code and flags

Last 2 bytes is code and flags. Code takes last 4 bits and can be client or server specific.
[5b, nothing yet][7b, flags][4b, code]

#### Specific flags

Flags can be combined, each flag has its own bit.

##### Compression

It has code **0x0080** and means data should be compressed. At the time of writing I use zstdlib. The sender should put data generated by it into the packet (as common data). Use it when you send big data or something.

##### Encryption

It has code **0x0040** and means data should be encrypted. Similar to compression but I use libsodium's crypto box seal. Use it to send important or secret information.

##### Checksum

It has code **0x0020** and means appending a 6-byte checksum. It has a strange, simple algorithm, just read it from the code. If receiver gets a different checksum it drops packet (or send a *nack*).

##### Need nack

It has code **0x0010**. It requires a checksum. When checksum differs from the one written in package, the receiver should send a *nack* to notify sender about bad packet. 

##### Nack

It has code **0x0100**. It is answer on *need nack* or *need ack*. The receiver sends it again and again until it gets good packet.

##### Need ack

It has code **0x0200**. It requires a checksum. When checksum differs from the one written in package, the receiver should send a *nack* to notify sender about bad packet.

##### Ack

It has code **0x0400**. It is answer on *need ack*. The receiver sends it when got good packet.

##### Seq

It has code **0x0800**. It asks for sorting packets. And set third from the end byte as thread id and fourth for id in thread queue. Uses 12th bit from the and as flag, that shows it is the last package.

#### Specific codes

The code is purpose of the packet, type of data, etc. But maybe later it will be removed or replaced.

##### Game data

Anything sent by game. Code **0x00**.

##### Greeting 

Means sender sends its public key for encryption. It has code **0x01**. Also server sends client id.

##### Init

Client opens connection. After that keys should be sent. It has code **0x02**.

##### Info

Client wanna know more about server: type, size of data, requirements, etc. May be merged with ping. It has code **0x03**.

##### Ping

Client waits for pong to calculate duration. It has code **0x04**.

##### File part

Server(yet) sends part of file. It has code **0x02**.
**Content structure**
`(2B, path size)(part)({path size}B path)`
It sends using *seq* method.

##### Pong

Answer for ping. It has code **0x03**.

##### Info (server)

Now wasn't written, but should be answer for info request.

# Thread

Data structure for sending **and** receiving packets sequentially.
It has 2^8 places. It used when u send package with **seq** flag.
There're 2^8 threads on server and 2 on client.
You can use only *id*\*2+1 for sending and *id*\*2+2 for receiving of servers threads. 

# Nack buffer

An 1024-length array for nacks waiting.
```
1024x8B/1024(B/KB) = 8 KB - pointers
1024*1024*1B/(1024*1024)(B/MB) = 1 MB - summary content
1024*2B/1024(B/KB)*2 = 4 KB - sizes and capacities
1024*2B*3/1024(B/KB) = 6 KB - additional data (like nack id, thread id, etc) approximately
1024 + 8 + 4 = 1040 KB - summary, not so many
```

# Synchronization

Server gives each peer id. Server itself has id 0. Using this number u can do some things. Id should be within the range [0, 128)
